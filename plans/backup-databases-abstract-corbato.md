# bekup — Open-source database backup manager

## Context
The repo `bekop-db` is empty (no commits yet). The goal is an open-source, self-hosted tool that schedules and runs backups of PostgreSQL, MySQL and MariaDB using each database's **native dump tools, version-matched by running them in the official Docker images**. It writes backups to Disk, S3 and SFTP, applies retention, restores on demand, and is managed through a React web UI that talks GraphQL to a Go backend. Later phases add an isolated external API with push notifications (Phase 2) and native iOS/Android apps (Phases 3–4).

**Security is the top priority: no compromises.** When convenience and security conflict, security wins. Any weakened setting (encryption/TLS opt-out) requires an explicit admin action with step-up auth, shows a permanent warning badge, raises a security alert and is audited.

This file is the **living, checkable plan**. Update it after every completed task (`- [ ]` → `- [x]`). Every decision is recorded in **`docs/DECISIONS.md`** (the decision log); `AGENTS.md` holds a short architecture summary + working conventions and links to it.

## Architecture

### Components & trust boundaries
```
browser ──HTTPS──> Traefik | nginx-proxy (TLS termination, profile) ──HTTP (net: frontend, internal)──┐
                   ┌──────────────────────────────────────────────────────────────────────────────────┘
                   bekup serve  (GraphQL, sessions, UI, scheduler, River workers: backup/restore/
                   │             retention/notify; pipeline; uploads to destinations)
                   ├─ pgx (role bekup_app) ─────────> Postgres app DB
                   ├─ HTTPS/SFTP/SMTP (SSRF-guarded) > destinations, SMTP, webhooks
                   └─ gRPC + mTLS (net: runner-ctl) ─> bekup runner ── docker.sock ──> dockerd
                                                        │ per run: creates an internal Docker network,
                                                        │ joins it, runs a TCP proxy / SSH tunnel to ONE target
                                                        └─> dump container (only on the per-run internal net;
                                                            ExtraHosts: db-host → runner proxy IP) ──> target DB
```
- **serve** can reach: Postgres, the runner (mTLS), destinations/SMTP/webhooks. It **cannot** reach target DBs or Docker.
- **runner** is the only component with Docker access. It has no DB access, minimal code, accepts no inbound traffic except mTLS gRPC on an internal network, and runs only allowlisted images with container specs it builds itself. It enforces a **target allowlist** (CIDRs/hosts in its own config; loopback, link-local and metadata are always denied).
- **dump containers** sit alone on a per-run `internal: true` network. They can reach only the runner's per-run proxy, which forwards to exactly one target. They can't reach the runner's gRPC port, other runs' tunnels or the internet. Because `ExtraHosts` maps the real DB hostname to the proxy, TLS `verify-full` still works end to end (TLS runs client↔DB through the TCP proxy).

### Runner (`bekup runner`)
- gRPC over mTLS (TLS 1.3). `bekup certs init|rotate` creates a private CA plus per-component certs (ed25519). The CA key never ends up on a shared volume: each component gets only its own key + the CA cert via a Docker secret, clients are identified by SAN, and cert expiry is exposed as a metric/alert. Keepalive is configured; stream chunks are ≤1 MiB; backpressure comes from gRPC flow control (no unbounded channels).
- RPCs (typed, no free-form commands): `Probe` (test connection / detect version / list DBs via Go drivers inside the runner, with normalized errors so it can't be used as a port scanner), `Dump`, `DumpGlobals`, `Restore` (client-streaming), `CreateDatabase`, `RenameSwapDatabase` (PG), `VerifyDump`, `PrePull`, `Health`.
- **Image allowlist** comes from the runner's own config: an embedded `catalog.toml` (engine → version → image@multi-arch-index-digest, client binary names, `legacy` flag for EOL versions such as PG13/MySQL 8.0) plus an optional mounted extra-images file. Never from the DB; a connection's "image key" can only select an allowlisted entry.
- **Fixed container spec**: argv arrays only, `ReadonlyRootfs`, tmpfs `/tmp` (noexec, nosuid), `HOME=/tmp`, `MYSQL_HISTFILE=/dev/null`, `CapDrop: ALL`, `no-new-privileges`, non-root UID, default seccomp, memory/CPU/pids limits, no mounts, not privileged, label `bekup.run_id`.
- **Secret preamble**: a fixed wrapper reads **base64, length-prefixed** records from stdin (password; optional CA/client cert/key for TLS) and writes them to 0600 files in tmpfs (MySQL option-file values are escaped). It then `exec`s the tool with fixed argv. Secrets never appear in env, args or inspect output; the runner zeroes its buffers after the call.
- Validation: DB names must be in the server-reported list, pass a strict charset check and must not start with `-`. PG gets a quoted `dbname=` conninfo (never a raw name/URI). Hosts and ports are validated against the target allowlist. Unknown fields are rejected. Validators are fuzz-tested.
- **SSH tunnels** (`x/crypto/ssh`, key/password, **mandatory host-key pin** with TOFU fingerprint confirmation in the UI, no bypass) terminate inside the runner's per-run proxy.
- An orphan reaper (by label) removes containers and networks on start; the runner kills the container on cancel, timeout or stream loss. The runner joins per-run networks via self-container detection (`BEKUP_RUNNER_CONTAINER` overrides it). Distroless nonroot plus a `group_add` docker GID (configurable). Docs cover rootless Docker / userns-remap as extra hardening.

### Engines (MySQL and MariaDB are strictly separate engines)
- **Postgres**: `pg_dump -Fc -Z0` (pipeline compresses). **Client major ≥ server major is enforced** (block, not just warn); the restore image is max(dump version, target version). Globals: `pg_dumpall --globals-only`, falling back automatically to `--no-role-passwords` for non-superusers (RDS etc.). Post-dump check: `pg_restore --list`. Restore: `pg_restore --exit-on-error --no-owner` (option) into a temp DB `…__bekup_restore_<id>`, then swap (rename) for overwrites. Globals restore via `psql --no-psqlrc -v ON_ERROR_STOP=1` is a **separate admin-only action**. Only client versions with the `\restrict` fix (CVE-2025-8714) are pinned. Note: piped `-Fc` gives no parallel restore; staged restores read from a file.
- **MySQL**: `mysqldump --single-transaction --routines --triggers --events --hex-blob --no-tablespaces --default-character-set=utf8mb4 --set-gtid-purged=OFF`, without `--databases`. Warns on non-InnoDB tables. Post-dump check: exit code + "Dump completed" trailer. Restore: `mysql --system-command=OFF --local-infile=0 --default-character-set=utf8mb4 <db>`.
- **MariaDB**: `mariadb-dump` with equivalent flags; restore with `mariadb --sandbox --local-infile=0`. Binary names come from the catalog (MariaDB ≥11 images have no `mysql*` names).
- **TLS to target DBs with certificate pinning**:
  - *Capture*: `Probe.FetchServerCertificate` in the runner (pgx / go-sql-driver with a capturing `VerifyPeerCertificate`; handles the PG SSLRequest and MySQL in-protocol TLS upgrade) returns the chain, subject/SAN, validity and SPKI SHA-256. An admin confirms the pin in the UI (step-up, audited). The pin is the self-signed leaf or the issuing CA.
  - *Enforcement*: the pinned cert reaches the dump container via the stdin preamble as its **only** trust anchor (`sslrootcert` + `sslmode=verify-full`; `--ssl-ca` + `--ssl-mode=VERIFY_IDENTITY` for MySQL; `--ssl-ca` + `--ssl-verify-server-cert` for MariaDB). Before every run the runner also checks the **leaf SPKI pin** in Go.
  - *Mismatch*: the run fails hard and a security alert fires. Re-pinning needs an admin with step-up and is audited. A backup pin can be staged ahead of a planned rotation. Expiry warnings fire 30/7 days before the pinned cert expires.
  - *Downgrade*: switching a connection to TLS-off/unpinned needs an admin, is audited, raises an alert and shows an "insecure transport" badge.
  - Docs recommend a dedicated, non-superuser backup role and restore role.

### Backup & restore pipelines
- **Backup (worker)**: runner stream → counter → zstd → age (default on; `SetMaxWorkFactor` bounded) → SHA-256 → fan-out with a **bounded buffer per destination**. A destination that fails or lags beyond a threshold is dropped and the run becomes `partial`. Disk/SFTP write `*.partial` and rename atomically. S3 uses multipart with ≥64 MiB parts (configurable; memory = part × concurrency), aborts on failure, sets `RequestChecksumCalculation=WhenRequired` for S3-compatible stores, and applies Object Lock retention headers when configured. Layout: `{prefix}/{job-slug}/{2026-10-26T030000Z}/{enc(db)}.{dump|sql}.zst.age` + `manifest.json`.
- **Manifest**: minimal content (artifact names, sizes, sha256, engine/version, timestamps, run/job IDs, encryption recipient fingerprint, passphrase version), **signed with an ed25519 instance key carrying a key ID** (old public keys are kept). Restore cross-checks the manifest against DB records, which defeats replay of old manifests.
- **Restore (worker)**: stage the encrypted artifact to a scratch volume (`BEKUP_SCRATCH_DIR`, size-checked; plaintext-compressed staging for opt-out jobs is wrapped with an ephemeral age key) → verify hash + signature + DB cross-check → decrypt → decompress → runner `Restore`. User-supplied age identities **never go into River job args**; they go into an encrypted handoff table with a 15-minute TTL and are deleted after use. Staging files are deleted in all paths.
- **Offline recovery** (works without the bekup DB): `bekup verify` / `bekup decrypt` with a passphrase or identity, a documented file format, a destination **re-index/import**, passphrase export (admin, step-up, audited), and documentation for master-key escrow and the signing-key fingerprint.

### Platform choices (each becomes a docs/DECISIONS.md entry; summarized in AGENTS.md)
- **Go libs**: `pelletier/go-toml/v2` (config), `chi`, `gqlgen`, `pgx/v5` + `sqlc`, `goose` (embedded, forward-only in production), `riverqueue/river`, `grpc-go`, moby client (runner only), `x/crypto/ssh`, `pkg/sftp`, `aws-sdk-go-v2`, `klauspost/compress/zstd`, `filippo.io/age`, `go-webauthn/webauthn`, `pquerna/otp`, `robfig/cron/v3` (parser), `cobra`, `log/slog`, `prometheus/client_golang`. Generators are pinned as `go tool` deps. `time/tzdata` is embedded.
- **Configuration (`internal/config`)**:
  - *Search path* (first match wins, files are never merged):
    1. `--config <path>` argument (or `BEKUP_CONFIG`). If it's given and the file is missing, that's a hard error; there's no fallback.
    2. The local directory: `./bekup.toml` (serve/worker) or `./runner.toml` (runner).
    3. `/etc/bekup/bekup.toml` or `/etc/bekup/runner.toml`.

    If none is found, startup fails (except in `[dev]`/`--dev` mode, which runs on defaults). The loaded path is logged at startup and shown by `bekup config print`. Every candidate goes through the same safety checks: a regular file (no symlink to a writable location), owned by the running user or root, and not group- or world-writable.
  - Parsed with `pelletier/go-toml/v2` in **strict mode** (unknown keys = startup error, with line/column).
  - *Sections* (`bekup.toml`): `[server]` (listen, base_url, trusted_proxies), `[database]` (url_file, pool), `[security]` (master_key_file, session timeouts, argon2, password policy), `[runner]` (address, client cert/key/CA files), `[storage]` (disk_root, scratch_dir), `[workers]` (concurrency limits, timeouts), `[scheduler]`, `[notifications]` (rate limits), `[netguard]` (bootstrap allowlist), `[metrics]` (internal listen), `[log]` (level, format), `[dev]` (enabled + guardrail overrides).
  - *Sections* (`runner.toml`): `[listen]`, `[tls]` (server cert/key, client CA, allowed client SANs), `[docker]` (host, gid, resource limits), `[images]` (extra allowlisted images, pinned by digest), `[targets]` (allow/deny CIDRs + hosts), `[limits]`.
  - *Env overrides*: `BEKUP_<SECTION>_<KEY>` maps 1:1 to TOML keys (e.g. `BEKUP_SERVER_BASE_URL` → `[server] base_url`; the `BEKUP_*` names elsewhere in this plan follow that mapping). There's a generated list in the docs.
  - *Secrets*: secret-bearing keys exist **only** as `*_file` (e.g. `master_key_file`, `database.url_file`). Inline secret values in TOML or env are rejected (except in `[dev]` mode). bekup refuses to start if a secret file or the config file is group- or world-writable, or if a secret file is world-readable.
  - *Validation*: a typed struct with validation tags plus cross-field rules (https base_url outside dev, trusted_proxies required, paths exist, limits sane), all errors reported at once. `bekup config validate` and `bekup config print --redacted` (effective config with source per key: default/file/env/flag). Annotated `bekup.example.toml` and `runner.example.toml` ship in the repo; a test checks the examples cover every key. Mounted read-only in compose.
  - *Reload*: no hot reload (restart to apply), so there's no inconsistent mid-run state.
  - Runtime settings that admins change in the UI (SMTP, 2FA policy, SSRF allowlist) stay in the DB `settings` table; the TOML holds infrastructure/bootstrap config only.
- **Database access (our own app DB)**: **sqlc + SQL migrations; no ORM.**
  - *Migrations*: goose, plain `.sql` files in `internal/db/migrations/` (`NNNNN_description.sql` with `-- +goose Up/Down`), embedded via `embed.FS`. Applied by `bekup migrate` and automatically at startup (advisory-locked; one instance migrates, the others wait). Run as `bekup_owner`; the app runs as `bekup_app`, and grants live in the migrations. Forward-only in production (Down kept for dev/tests). Never edit a released migration.
  - *River's schema is vendored into our goose migrations* (SQL generated with `river migrate-get`), so there is **one migration system** and one version history.
  - *Queries*: every query lives in `internal/db/queries/*.sql` with sqlc annotations; sqlc (`pgx/v5` driver, `emit_interface`, `emit_pointers_for_null_types`, typed overrides for uuid/timestamptz/jsonb/enums) generates `internal/db/sqlc`. No hand-built SQL strings anywhere else (enforced by review + a lint rule); the only dynamic parts are sqlc's `sqlc.narg`/`sqlc.slice` params. Transactions go through a small `db.Tx(ctx, func(q *sqlc.Queries) error)` helper.
  - *Workflow*: `just migrate-new <name>` creates a migration; `just gen` runs sqlc + gqlgen + graphql-codegen; `just db-reset` rebuilds the dev DB. CI runs `sqlc vet` + `sqlc diff` (generated code must be committed and up to date), applies all migrations up → down → up on a fresh Postgres, and checks that migrations match `schema.sql` (a schema dump kept for review).
  - Each feature task adds its own migration + queries; task 0.4 sets up the framework, roles and core tables.
- **River config**: explicit per-worker `Timeout` (backup = job timeout, restore = its own); `MaxAttempts` (backup 2, **restore 1**, notify 10); `RescueStuckJobsAfter` > longest timeout; unique `ByState` = available/scheduled/running/retryable (excludes completed). Job args never contain secrets.
- **Scheduler**: no session advisory lock on pooled connections. Each tick (15s) runs `SELECT … FOR UPDATE SKIP LOCKED` + River unique insert + `next_run_at` advance in one transaction, which is safe across several `serve` instances. Sub-day intervals are absolute durations; intervals of a day or more use wall-clock time in the job's IANA zone (month-end clamped, nonexistent times shifted forward, ambiguous times take the first occurrence); robfig's DST behaviour is property-tested. Missed runs collapse into one catch-up run. Timestamps are stored as `timestamptz` and zones as IANA names.
- **Concurrency limits**: global runs, per-connection runs, downloads, argon2id hashing (semaphore), WS connections per user.
- **Credential encryption**: AES-256-GCM envelope; keyring from `BEKUP_MASTER_KEY_FILE` (env var only in dev mode); the key ID is in the ciphertext; AAD = `table:row_id:field`; a key-check value is verified at startup; `bekup keys generate|rotate`. Secrets are **write-only** in GraphQL (`hasPassword`) and zeroed after use.
- **AuthN**: argon2id (m=64MiB, t=3, p=1, rehash on change). Password policy: ≥12 chars, strength check, common-password list. `__Host-` cookie (HttpOnly, Secure, SameSite=Strict; the HTML shell doesn't depend on the cookie, so email deep links work); the token is stored as sha256; sessions carry an AAL and `stepup_at`, rotate on login and privilege change, have idle + absolute expiry, are all revoked on password change, and can be listed/revoked by the user. Lockout with backoff; generic, timing-safe errors. WebAuthn (RP ID from `BEKUP_BASE_URL`) + TOTP (replay protection via last used step) + recovery codes. **Step-up** (≤5 min) for secret changes, restores, download tickets, user/role changes, opt-outs, 2FA changes, passphrase export and key operations. Setup token: one-time, 1h TTL.
- **TLS termination**: Traefik (Let's Encrypt via labels) or nginx-proxy + acme-companion, as compose profiles. Both configs ship hardened: TLS 1.2+/1.3 only, modern ciphers, HSTS preload-ready, HTTP→HTTPS redirect, request size limits, SSE streaming (no buffering). `serve` listens only on the internal `frontend` network (its port isn't published). `BEKUP_TRUSTED_PROXIES` (CIDRs) is required outside dev mode, and `X-Forwarded-*` is ignored from anyone else. bekup also sets HSTS and the security headers itself (defence in depth).
- **Outbound TLS (not pinned)**: S3, SMTP and webhooks use system roots, `MinVersion` TLS 1.2, https/STARTTLS/implicit TLS required, with an optional admin-provided CA bundle (e.g. private S3).
- **HTTP hardening**: `BEKUP_BASE_URL` must be https outside dev mode, and all links are built from it (never from Host). Strict CSP (`script-src 'self'`; `style-src` settled in 0.8 against Radix/sonner, nonce if needed), HSTS, frame-ancestors none, nosniff, Referrer-Policy no-referrer. gqlgen allows **POST + `application/json` only** (no GET/multipart). Origin/`Sec-Fetch-Site` checks on mutations and the WS upgrade. Depth/complexity/size limits, introspection only for authenticated users, masked errors, per-IP and per-user rate limits, trusted-proxy list.
- **Notifications engine** (`internal/notify`): an event from the **typed catalog (D-161)**: *backup* `backup.started|succeeded|succeeded_with_warnings|partial|failed|canceled|missed|started_early`; *restore* `restore.started|completed|failed`, `test_restore.passed|warnings|failed`; *retention & storage* `retention.summary` (daily digest), `artifact.missing`, `destination.test_failed`; *job & config* `job.created|updated|disabled|enabled|deleted|encryption_changed`, `connection.pin_changed|tls_downgraded|host_key_changed` (staff; owners only for own jobs' job events); *security (mandatory)* `security.account`, `security.system`. Each event has a group, a default audience and a "problem" flag. **New-user defaults (D-161): every visible event → in-app inbox; email only for problem events; webhooks/push opt-in.** `*.started` events are low priority and collapsed per job within a short window. → a resolver computes recipients = shared channels on the job + every user who **may currently see the job** (authz checked at delivery time) with matching preferences → one River notify job per (recipient, channel), idempotent per event. Preference resolution: per-job override > per-event user preference > the D-161 defaults. Users must **verify their email address** (signed link) before email delivery. Payloads carry minimal data (job name, status, time, link built from `BEKUP_BASE_URL`), never secrets or DB contents. Per-user rate limiting/digest prevents floods (failures repeating within N minutes collapse). A webhook that fails repeatedly is auto-disabled and its owner is notified in the inbox.
- **Live subscriptions (SSE since 2.13; originally WS)**: cookie auth on upgrade; the session is re-validated periodically and on every event; authz runs at delivery time; the socket closes on logout, revoke or role change. NOTIFY payloads carry IDs only.
- **AuthZ**: central `internal/authz`, deny-by-default, `@hasRole` + per-object ownership checks; a matrix test covers every operation × role and CI fails when an operation is unmapped.
- **DB roles**: `bekup_owner` (migrations), `bekup_app` (runtime DML). **Audit log**: hash computed in a `SECURITY DEFINER` trigger under an advisory xact lock; REVOKE UPDATE/DELETE/TRUNCATE plus raising triggers; `bekup audit verify`; the chain head is signed periodically and exported to destinations/webhook; archival policy.
- **SSRF guard** (`internal/netguard`): a dial-time `Control` hook (defeats DNS rebinding) denies private/loopback/link-local/metadata ranges by default, with an admin allowlist. Used for webhooks, S3 endpoints, SMTP and SFTP; no redirects. Disk destinations are confined to `BEKUP_DISK_ROOT` via `os.Root`.
- **Downloads** (admins + owners): a mutation `createDownloadTicket` (step-up, audited; for `plain` mode with recipient encryption the identity is sent in the POST) returns a single-use 60s ticket bound to the session; `GET /api/download/{ticket}` streams with `Cache-Control: no-store` and a sanitized Content-Disposition filename. `plain` streams decrypt → decompress, producing a file usable directly with `pg_restore`/`mysql`; the download dialog shows the matching restore command.
- **Restore gate**: the `restoreArtifact` mutation needs a session with `aal2_at` ≤5 min old from a passkey/TOTP check (a password alone is not enough). Users without 2FA get `REQUIRES_2FA_ENROLLMENT`.
- **Temporary connections**: `connections.temporary` + `expires_at` + `created_for_restore_id`; they are excluded from job creation and listings (except in the restore wizard); a cleanup worker deletes them after the restore finishes or expires and zeroes `secret_enc`; their creation and use are audited.
- **Task runner**: the `justfile` uses `[group]`/`[doc]` attributes. The default recipe prints a banner + colored grouped help (dev, quality, security, build, db, keys, release) using `just --list --unsorted` formatting with NO_COLOR support. `just bump [patch|minor|major|<x.y.z>]` updates `VERSION`, `web/package.json` and `CHANGELOG.md` (git-cliff from conventional commits), then makes a signed commit + annotated tag (refusing when the tree is dirty or not on main). The version is injected via `-ldflags` and shown in the UI and `bekup version`.
- **Logging/limits**: slog redaction handler; known secret values are redacted from runner log lines; caps on run-log lines and line length.
- **Supply chain**: images pinned by digest (Renovate), Actions pinned by SHA, `govulncheck`, `gosec`, `osv-scanner`, Trivy, SBOM (syft), cosign keyless signing + provenance. bekup images are distroless nonroot with a read-only root filesystem.
