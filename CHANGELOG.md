# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
From the first release on, this file is maintained by
[git-cliff](https://git-cliff.org/) from Conventional Commits via `just bump`.

## [Unreleased]

### Added

- Project scaffold: Go module, package layout, license, documentation
  skeleton, decision log (`docs/DECISIONS.md`) and contributor/agent guide
  (`AGENTS.md`).
- Runtime config reload (D-200, proposed): `bekup serve` and `bekup worker`
  re-read `bekup.toml` on an admin request (Admin → Settings →
  Configuration, every process) or on SIGHUP (one process) and apply a
  conservative set of live keys; other changed keys are reported as
  needing a restart, an invalid file is refused, every reload is audited
  and a weakening change alerts every admin.
- Container-only compose install (D-203, proposed): `bekup setup init |
  upgrade | check` writes and maintains a complete deployment directory
  from the image alone (compose file pinned to the image digest, deploy
  assets, `.env`, minimal `bekup.toml`/`runner.toml`, database passwords,
  master key, private CA and mTLS certificates with their owners), run in a
  one-shot root container with only `CAP_CHOWN` and no network. The image
  now embeds `docker-compose.yml`, the example configs and
  `deploy/{postgres,traefik,nginx}`.
- Release workflow (D-204, proposed): a signed `vX.Y.Z` tag on `main`
  builds a multi-arch image after the full CI passed, pushes it to
  `ghcr.io/jlentink/bekup` by digest, scans it with Trivy, signs it with
  cosign (keyless) with SBOM and build provenance attestations, then tags
  `X.Y.Z` (and `latest` for the highest version) and creates the GitHub
  release with the digest and the `cosign verify` and `bekup setup`
  commands.
- Compose-first onboarding (D-205, proposed): each release publishes three
  attested compose files pinned to the release image by digest:
  `compose.yaml` (bekup with its own Traefik), `compose.traefik-external.yaml`
  (behind an existing Traefik) and `compose.npm.yaml` (behind Nginx Proxy
  Manager), plus `SHA256SUMS` and a cosign bundle per file. Install: save
  one as `compose.yaml`, `docker compose run --rm setup`, `docker compose
  up -d`. The new `setup` service (profile `setup`, root with only
  `CAP_CHOWN`, no network, no logs) runs `bekup setup` from the pinned
  image; setup recognizes the variant and never writes `compose.yaml`.
  External proxies reach `serve` over a dedicated `bekup-proxy` link
  network with fixed addresses (`trusted_proxies` exactly the proxy's /32).
- `bekup setup compose --variant traefik|traefik-external|npm|full
  [--image <pinned>]` prints a compose variant; `just compose-examples`
  writes them to `dist/compose/`. The variants are overlays of
  `docker-compose.yml`, never copies.
- The three compose files are committed in `deploy/compose/` (D-205
  amendment 3, proposed), generated by `just gen` and never edited by hand,
  so the install works before the first release: they equal the release
  assets except for the `x-bekup-image` line, which takes the image from
  `BEKUP_IMAGE` (`${BEKUP_IMAGE:?...}`, no default). `BEKUP_IMAGE=<pinned>
  docker compose run --rm setup` checks that it is digest-pinned and names
  the binary's version, writes it to `.env` and records it; `setup check`
  requires `.env` to name the recorded image without a shell override; an
  upgrade is `BEKUP_IMAGE=<new> docker compose run --rm setup upgrade`
  (rewrites the `.env` line). Renovate ignores `deploy/compose/**` (run
  `just gen` on its PRs); the release workflow requires the tag's committed
  files to equal the release assets except for the image line.
  `just publish` prints the pin with its tag (`<repo>:<tag>@sha256:...`).
- `setup check` (and `setup init`/`upgrade`) lints the project docker
  compose would run: `compose.yaml`, `compose.override.yaml` and `.env`
  resolved with compose-go, the Docker Compose loader (every document,
  merge key, `!reset`/`!override`, `extends`, `${VAR}`), then checked with
  an allowlist (pinned images; every service read-only, `cap_drop: [ALL]`,
  `no-new-privileges`, non-root; binds only inside the deployment
  directory except the runner's Docker socket; no privileged containers or
  hooks, host namespaces, devices, extra capabilities, host-path volumes,
  secrets or configs, published ports on internal services, changes to the
  setup service). Multi-document compose files and `DOCKER_HOST`-style
  variables in `.env` are refused. It also checks the link network of the
  external variants. New dependency: `github.com/compose-spec/compose-go/v2`
  (Apache-2.0).
- Ownership fixes (`setup init`, `upgrade`, `check --fix-ownership`) change
  modes and owners only on descriptors opened without following symlinks.
- `bekup serve` warns (rate-limited) when `X-Forwarded-For` arrives from a
  peer that is not in `server.trusted_proxies`, a sign of a misplaced proxy.

### Changed

- The deployment compose file is now `compose.yaml` and the override
  `compose.override.yaml` (setup-first installs too); the repository source
  stays `docker-compose.yml`. `bekup setup init` without a `compose.yaml`
  refuses with the release URL; `--write-compose --variant ...` keeps the
  setup-first path (the `full` variant with nginx or your own proxy), and
  `setup upgrade` of such a deployment needs `--write-compose`.
- `docker-compose.yml` names the bekup image only in the new
  `x-bekup-image` line, gets the `setup` service, and mounts every
  `./deploy/...` file with the long syntax, read-only and
  `create_host_path: false`.
- Release notes show the three-step compose install instead of the
  `docker run ... setup init` command.
- Dev only: the `runner-host` network of `just dev-runner` (D-201) moved
  from `10.213.253.0/24` to `10.213.254.0/24` (the old range is now the
  `bekup-proxy` link network); run `just dev-down` and
  `docker network rm bekup_runner-host` once.
- The `bekup-proxy` link network is created with `--gateway` and an
  `--ip-range` that excludes the fixed proxy and `serve` addresses
  (`setup init` prints the command for custom addresses), so no other
  container can take them. The docs show attaching the proxy next to its
  existing networks.
- `setup check` is run as `docker compose -f compose.yaml run --rm setup
  check` (the override cannot change the checking container; it is still
  linted), or with a plain hardened `docker run` of the pinned image.
- The release job publishes the compose files only when their digest
  matches the one the signing `compose` job reported.

### Removed

- Mobile apps and the reserved push notification channel (D-206, proposed):
  `notify.ChannelPush` and the disabled Push column of the notification
  matrix are gone. Migration `00033_drop_push_channel` deletes stored
  `push` preference rows and recreates the `notification_channel` and
  `user_channel_type` enums without `push` (inbox, e-mail and webhook
  preferences, deliveries and personal channels are kept).
